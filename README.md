# منصة رقمنة المخطوطات — النسخة المستقلة (بدون Docker)

تعمل بعملية Python واحدة: SQLite بدل Postgres، معالجة خلفية مدمجة بدل
Celery/Redis، وواجهة ويب مدمجة يقدّمها الخادم نفسه بدل React/Node.

> مُختبَرة فعليًا من البداية للنهاية على صفحة من مخطوطة "تفضيل السلف على
> الخلف": رفع → معالجة خلفية → OCR (1665 حرفًا) → قائمة مراجعة → تصحيح →
> بحث بالتطبيع العربي → تصدير عيّنات تدريب. كل خطوة تحققت ببرمجية اختبار.

## المتطلبات

1. **Python 3.10 أو أحدث** — من python.org (على Windows فعّل "Add Python to PATH" أثناء التثبيت)
2. **Tesseract OCR بالعربية** (اختياري لكن ضروري للتعرف الضوئي):
   - **Windows**: حمّل مثبّت UB-Mannheim من
     github.com/UB-Mannheim/tesseract/wiki — أثناء التثبيت اختر
     "Additional language data" ثم Arabic. أعد تشغيل الجهاز بعد التثبيت.
   - **macOS**: `brew install tesseract tesseract-lang`
   - **Linux**: `sudo apt install tesseract-ocr tesseract-ocr-ara`
   - إن لم تثبّته: المنصة تعمل (رفع + تحسين صور + الواجهة) ويُعطَّل OCR فقط
     مع رسالة توضيحية داخل الواجهة.

## التشغيل

- **Windows**: انقر نقرًا مزدوجًا على `run.bat`
- **macOS/Linux**: `./run.sh`

أول تشغيل يثبّت المتطلبات تلقائيًا (2-5 دقائق حسب الإنترنت). التشغيلات
التالية فورية. ثم افتح المتصفح على **http://localhost:8000**

## الاستخدام

1. **رفع مخطوطة**: من التبويب الأول — PDF أو صورة. يُحفظ الأصل دون تعديل
   مع بصمة SHA-256، وتبدأ المعالجة تلقائيًا في الخلفية.
2. **المكتبة**: تابع حالة المعالجة (قيد المعالجة ← مكتملة)، وانقر أي
   مخطوطة لعرض صفحاتها ونصوصها مع متوسط الثقة.
3. **المراجعة**: الكلمات منخفضة الثقة مرتّبة بالأكثر غموضًا أولًا، كل
   واحدة مع قصاصة صورتها الأصلية. كل تصحيح يُحفظ كعيّنة تدريب ويُحدّث
   نص البحث فورًا.
4. **البحث**: بتطبيع عربي — يتجاهل التشكيل وفروق الهمزات (أ/إ/آ=ا)
   والياء/الألف المقصورة والتاء المربوطة.
5. **تصدير بيانات التدريب**: `http://localhost:8000/api/training/export`
   يعيد كل تصحيحاتك بصيغة JSON جاهزة لضبط نموذج HTR لاحقًا.

## أين تُحفظ بياناتك

كل شيء داخل مجلد `data/` بجوار البرنامج: `data/archive/` الأصول المحفوظة،
`data/derived/` الصور المعالَجة، `data/manuscripts.db` قاعدة البيانات.
انسخ مجلد `data/` احتياطيًا وستحفظ كل عملك.

## توقعات الدقة (بصراحة)

المحرك المدمج (Tesseract) خط أساس مُدرَّب على النص المطبوع؛ على الخط
اليدوي التاريخي أعطى في اختبارنا الفعلي متوسط ثقة ~26% — لذلك حلقة
المراجعة ليست ميزة إضافية بل الطريق الأساسي للدقة. تصحيحاتك المتراكمة
(تصدير `/api/training/export`) هي وقود ضبط نموذج HTR متخصص لاحقًا.
النسخة الكاملة (Docker) في المشروع الأكبر تتضمن بنية ذلك كاملة.

## مشاكل شائعة

- "python غير معروف" على Windows: أعد تثبيت Python مع تفعيل Add to PATH.
- المنفذ 8000 مشغول: أغلق البرنامج الآخر، أو عدّل السطر الأخير في app.py
  إلى `port=8080` وافتح localhost:8080.
- OCR معطَّل رغم تثبيت Tesseract على Windows: أعد تشغيل الجهاز، أو أضف
  مجلد Tesseract (عادة C:\Program Files\Tesseract-OCR) إلى PATH.

# النشر على الإنترنت عبر GitHub (بدون تثبيت أي شيء على جهازك)

> ملاحظة: Laravel Cloud مخصص لتطبيقات PHP فقط ولن يعمل مع هذه المنصة
> (Python). البدائل المكافئة أدناه تنشر من GitHub مباشرة، وملف Dockerfile
> المرفق يعمل على خوادمها هي — أنت لا تثبّت Docker على جهازك إطلاقًا،
> وTesseract العربي مضمَّن فيه تلقائيًا.

## الخطوة أ: رفع الكود إلى GitHub (من المتصفح، بلا أوامر)

1. أنشئ حسابًا على github.com إن لم يكن لديك.
2. اضغط + أعلى اليمين ← New repository ← الاسم مثل
   `manuscript-platform` ← اختر Private (أو Public) ← Create repository.
3. في صفحة المستودع الفارغ اضغط رابط "uploading an existing file".
4. اسحب كل ملفات هذا المجلد إلى الصفحة: `app.py`، `Dockerfile`،
   `render.yaml`، `requirements.txt`، `.gitignore`، ومجلد `static`
   (اسحب الملف `index.html` وسيسألك GitHub عن المسار — اكتب
   `static/index.html`). لا ترفع `venv` أو `data`.
5. اضغط Commit changes.

## الخطوة ب (الخيار 1): النشر على Render — مجاني والأسهل

1. سجّل في render.com بحساب GitHub نفسه.
2. اضغط New + ← Web Service ← اربط حساب GitHub واختر مستودعك.
3. Render سيكتشف `Dockerfile` تلقائيًا. اختر الخطة Free ← Create Web Service.
4. انتظر 5-10 دقائق للبناء الأول، ثم ستحصل على رابط عام مثل
   `https://manuscript-platform.onrender.com` — شاركه مع من تشاء.

قيود الخطة المجانية في Render يجب معرفتها بصراحة:
- الخدمة "تنام" بعد 15 دقيقة خمول؛ أول طلب بعد النوم يتأخر ~50 ثانية.
- **القرص مؤقت**: كل ما ترفعه يُمسح عند إعادة النشر أو إعادة الإقلاع.
  مناسبة للتجربة والعرض، وليست لأرشفة حقيقية.
- للحفظ الدائم على Render: خطة Starter (~7$/شهر) + Persistent Disk من
  إعدادات الخدمة، واربطه بالمسار `/app/data`.

## الخطوة ب (الخيار 2): Railway — تخزين دائم بسهولة

1. سجّل في railway.app بحساب GitHub.
2. New Project ← Deploy from GitHub repo ← اختر مستودعك (يكتشف Dockerfile).
3. مهم للحفظ الدائم: من الخدمة ← Settings ← Volumes ← Add Volume
   واربطه بالمسار `/app/data` — بهذا تبقى مخطوطاتك وقاعدة البيانات
   محفوظة عبر إعادات النشر.
4. من Settings ← Networking ← Generate Domain للحصول على رابط عام.
5. التكلفة: رصيد تجريبي عند التسجيل ثم حسب الاستخدام (~5$/شهر لخدمة صغيرة).

## أيهما تختار؟

- تجربة سريعة ومشاركة عرض: **Render Free**.
- استخدام حقيقي بأرشيف دائم: **Railway مع Volume** أو Render Starter بقرص دائم.
- مخطوطات كبيرة كثيرة (عشرات الجيجابايت): ارجع لنسخة Docker Compose
  الكاملة على خادم VPS خاص (المشروع الأكبر المسلَّم سابقًا).

## تنبيه أمني قبل النشر العام

الرابط الناتج عام: أي شخص يعرفه يستطيع الرفع والمراجعة. النسخة الحالية
بلا تسجيل دخول عمدًا للبساطة المحلية. إن نشرتها عامة، اجعل المستودع
والرابط خاصين بفريقك، أو أخبرني لأضيف طبقة دخول بكلمة مرور بسيطة.
